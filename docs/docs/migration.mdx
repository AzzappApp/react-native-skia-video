# Migrating to 1.0

Version 1.0 targets [React Native Skia v3](https://wcandillon.github.io/react-native-skia/docs/getting-started/migration/),
which renders with Skia Graphite (Metal on iOS, Vulkan on Android). Graphite no
longer accepts native textures: video frames reach Skia through textures of its
GPU device, created with [React Native WebGPU](https://wcandillon.github.io/react-native-webgpu/).
The library copies each decoded frame into such a texture on the GPU and hands
you an `SkImage`.

## 1. Upgrade React Native Skia and install React Native WebGPU

Follow the [React Native Skia v3 migration guide](https://wcandillon.github.io/react-native-skia/docs/getting-started/migration/):
the package is now `react-native-skia` (instead of `@shopify/react-native-skia`).

:::caution Minimum versions
This library now requires **iOS 16** and **Android 9 (API level 28)**, React
Native Skia 3.7.3 and React Native WebGPU 0.19.0 or above.
:::

```sh
yarn remove @shopify/react-native-skia
yarn add react-native-skia react-native-webgpu @azzapp/react-native-skia-video@^1.0.0
```

React Native Skia and React Native WebGPU must be built against the same Dawn
release: the native build fails with a `Dawn version mismatch` error otherwise.
Upgrade them together (see the [compatibility table](https://wcandillon.github.io/react-native-webgpu/docs/integrations/react-native-skia#compatibility)).

On Android, React Native WebGPU must be built with NDK 27: see
[Android NDK](/docs/getting-started#android-ndk).

## 2. Draw `frame.image`

`VideoFrame.texture` is replaced by `VideoFrame.image`, an `SkImage` ready to be
drawn:

```diff
- const image = Skia.Image.MakeImageFromNativeTextureUnstable(
-   frame.texture,
-   frame.width,
-   frame.height
- );
- canvas.drawImageRect(image, src, dst, paint);
+ canvas.drawImageRect(frame.image, src, dst, paint);
```

:::note
`frame.texture` still exists, but it is now the WebGPU `GPUTexture` that
`frame.image` samples (for a WebGPU pass that reads the frame), not a native
texture: it can no longer be wrapped into an image. Draw `frame.image`.
:::

With `useVideoPlayer`:

```diff
  const videoImage = useDerivedValue(() => {
    const frame = currentFrame.value;
-   if (!frame) return null;
-   return Skia.Image.MakeImageFromNativeTextureUnstable(frame.texture, frame.width, frame.height);
+   return frame?.image ?? null;
  });
```

## 3. Don't keep frames around

The images are owned by the player (or composition player): an image only
shows its frame until the next one is produced. Don't dispose them, and use
`image.makeRasterImageSync()` if you need a lasting copy (a thumbnail for
instance).

## 4. Android frames are upright

On Android, frames are now rotated upright when they are converted: their
`rotation` is always 0, and `width` / `height` are the displayed size (a
portrait phone clip is a 1080×1920 frame). On iOS nothing changes: frames are as
stored in the file, with the rotation to apply (the same clip is a 1920×1080
frame with a `rotation` of 90). Code that applies `frame.rotation` keeps working
on both; code that rotated Android frames by the video's rotation must stop.
The `rotation` of the `ready` event of `useVideoPlayer` follows the same rule.

## 5. Low-level APIs

Only if you call the native objects directly (the hooks and
`exportVideoComposition` do it for you):

- `VideoPlayer.decodeNextFrame()` and `decodeCompositionFrames()` return
  `DecodedFrame`s, the native buffers of the decoders (a `CVPixelBufferRef` on
  iOS, an `AHardwareBuffer*` on Android), rather than `VideoFrame`s: the library
  turns them into Skia images.
- `VideoEncoder.encodeFrame(texture, time)` is replaced by `beginFrame(time)`,
  which on iOS hands out the native buffer to render the frame into (on Android
  the frame is presented to the encoder's `nativeWindow`), and `endFrame(time)`,
  which encodes it.

## 6. TypeScript

`VideoFrame.texture` is typed `GPUTexture`, a global type of
[`@webgpu/types`](https://www.npmjs.com/package/@webgpu/types): it is a
dependency of the library and its declarations reference it, there is nothing to
install or configure.

## What's new

- `maxLongSide` (`useVideoPlayer` and composition video items): caps the long
  side of the decoded frames, keeping the aspect ratio. Safe for rotated videos,
  unlike `resolution`.
- `volume` on the composition player: a master volume on top of the items'.
- `audioFadeIn` / `audioFadeOut` on composition items: linear volume ramps,
  during playback and in the export.

## What doesn't change

`useVideoPlayer`, `useVideoCompositionPlayer`, `exportVideoComposition`, the
composition model and the audio support keep the same API.
